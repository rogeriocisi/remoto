Spinal cord · motoneuron pools · muscle · proprioceptors · Version 3, 2026

Spinal motor circuits, simulated spike by spike.

ReMoto is an open-source simulator of the spinal cord networks that control human muscles: motoneuron pools, interneurons, sensory afferents, muscles and proprioceptors of the ankle, modeled from membrane conductances up to joint torque. It runs in a browser or on the command line, and every run can be repeated exactly.

1The model

From a descending command to the torque at the ankle

ReMoto reproduces, neuron by neuron and motor unit by motor unit, the chain that turns a command from the brain into muscle force. Each element has its own mathematical model, usually built on voltage- or transmitter-dependent ionic conductances.

Because every level is simulated, one run can be read at several scales: the membrane potential of a single motoneuron, the firing statistics of a pool, the electromyogram, the force of a muscle and the torque at the joint. The simulated nuclei control flexion and extension of the human ankle: soleus (SOL), medial gastrocnemius (MG), lateral gastrocnemius (LG) and tibialis anterior (TA).

It is used to interpret neurophysiological experiments in humans, to propose and test hypotheses about spinal processing, to check an experimental protocol before running it, and to teach neurophysiology.

Motoneurons
Two-compartment (soma and dendrite) conductance-based models of types S, FR and FF, with sodium, fast and slow potassium channels and a persistent inward current in the dendrite. Thresholds, sizes and conduction velocities vary along the pool, which gives orderly recruitment.
Interneurons
Renshaw cells, Ia reciprocal inhibitory interneurons, Ib interneurons and group II interneurons, for the extensor and flexor sides.
Afferents
Ia, II and Ib fibers, driven by the muscle spindle and Golgi tendon organ models or by electrical stimulation of the nerve.
Descending tracts
Populations of axons firing as point processes (Poisson, gamma or Gaussian intervals), with the mean rate constant or modulated by a sine, ramp, square wave or other waveform.
Synapses
Conductance changes with their own kinetics, delay and connectivity, with optional short-term depression or facilitation.
Muscle
Each motoneuron spike produces, after its conduction delay, a motor-unit action potential and a twitch. Their sums are the EMG and the muscle force. Twitch models or a Hill-type muscle with tendon can be chosen.
Proprioceptors
Muscle spindle (Mileusnic or Prochazka models) with Ia and II outputs, and Golgi tendon organ (Crago model) with Ib output.
Joint
The ankle as an isometric joint, as an inverted pendulum for upright stance, or in a position task against a load.
Stimulation
Electrical pulses on the tibial and common peroneal nerves, with orthodromic and antidromic propagation, for M waves and H reflexes; current injected into chosen neurons.
Scale
The scenario with every element switched on has 2,110 motoneurons, 2,800 interneurons, 2,930 afferent fibers and 1,500 descending axons.
2Version 3

The published models on a platform that runs today

ReMoto was developed over more than a decade at the Biomedical Engineering Laboratory of the University of São Paulo. Its website depended on Java applets and on server software that no longer receives security updates. Version 3 keeps the models and replaces everything around them.

  1. Opens in any current browser

    No applets and no plug-ins. Simulations report their progress live, and results are drawn as interactive charts that download as CSV or PNG.

  2. No account, no database

    Each browser gets a private working area, identified by a 30-day cookie, so the work survives closing the browser and server restarts. To keep it longer or move it to another computer, export scenarios as JSON and whole runs as a ZIP, and import them there. No personal data is stored.

  3. Reproducible by construction

    Every run stores the exact scenario, the random seed and the engine version. The same three things give the same results, bit for bit, on any number of threads.

  4. The editor and results you know

    The scenario editor and the results screen follow the original site: the same menus, screens, fields, units and limits, from descending commands and conductances to EMG filters, spike statistics and FFT.

  5. A command line for scripts and clusters

    The JSON file you export from the site runs unchanged without a server, and writes every result as CSV. The original database can be converted to scenarios without installing it.

  6. Shared fairly in a classroom

    Several people can simulate at once. A round-robin queue keeps one visitor’s large batch from holding up everyone else, with limits per browser and per address.

  7. One file to deploy

    The web application is a single JAR with an embedded server, run as a system service. There is no database to back up and no identity provider to configure.

  8. Faster, with the same numbers

    Motoneurons and interneurons are updated in parallel while everything that draws random numbers stays in order, so the output does not depend on the thread count.

3Validation

Checked against the original, bit for bit

A new platform is only useful if the published results still come out of it. Each family of models was moved under one rule: the output had to match the original code exactly before the old code was removed.

These checks run as automated tests on every change, so a refactoring that alters a single bit of the output is caught at once.

  • The whole original database. All 30 configurations stored in the legacy database give the reference results recorded while the original data-access code was still assembling them.
  • Golden master. For the three public scenarios of the old site, force, spikes, torque, EMG and every other output match stored reference hashes.
  • The database without the database. The reader reproduces the rounding, truncation and row ordering of the original database engine, because the order of rows decides the order in which neurons are created and random numbers are drawn.
  • Editor against the original. Editing every screen and saving writes the same tables that the original site wrote; saving without editing changes nothing.
  • One thread against four. The public scenarios give identical output with any number of threads, and a worker thread that tries to draw a random number stops the run instead of silently changing it.
  • Synapses against the analytical solution. The synaptic conductance follows the closed-form solution of Lytton (1996) during and after each pulse.

What deliberately differs from the legacy code

  • Seeded random numbers. The original drew from unseeded generators. Version 3 routes every draw through one generator started from the scenario seed.
  • Synaptic decay. A change made to the legacy code in December 2016 left the synaptic conductance frozen between events. The engine goes back to the closed-form solution used before that change. Results from different engine versions should not be compared.
  • Gamma-process tracts. The original site never saved the order of the gamma process, so stored configurations with gamma tracts fired only at time zero. The public scenarios that had them now use Poisson tracts with the same mean interval, and the editor saves the order.

4Run it

Clone, start, simulate

You need JDK 25. Maven is downloaded by the wrapper included in the repository.

In the browser

$ git clone https://github.com/rogeriocisi/remoto.git
$ cd remoto
$ scripts/start.sh        # Linux, macOS, Git Bash
> scripts\start.cmd       # Windows, cmd
> .\scripts\start.ps1     # Windows, PowerShell

Then open http://localhost:8080. There is no login. Pick a public scenario and press Run, or copy it and change it in the editor. The start scripts look for a JDK 25 even when an older Java is the default; an optional argument sets the port.

On the command line

$ ./mvnw -pl remoto-cli -am package -DskipTests
$ java -jar remoto-cli/target/remoto-cli-3.0.0-SNAPSHOT.jar \
    run scenarios/remoto-17-default-soleus-contraction.json \
    --duration-ms 500 --threads 4 -o results/soleus

The output folder receives the frozen scenario, a manifest with the seed and engine version, and one compressed CSV per result. validate checks scenario files and export-legacy converts configurations from the original database.

The models are detailed, and therefore slow: one simulated second of the public scenarios takes about 17 to 30 seconds on four cores (Table 2). The simulator’s interface is available in English and Portuguese; the editor and the results menus keep the English labels of the original. Build instructions, the REST API, the scenario format and the deployment guide are in the README and in the full documentation (in Portuguese).
